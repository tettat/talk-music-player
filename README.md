# talk 私人音乐播放器

本机播放器：QQ 音乐搜索、独立播放、自己的收藏和列表，现已增加听歌统计、歌词提取和本机音乐模型分析。Kimi 负责视觉及本次增量设计，沿用暖石墨与青柠色，说明仅放在本文，不堆在页面里。

## 安装与打开

当前交付是 **Windows x64 源码运行版**，不是已经制作好的独立安装包。源码不依赖特定用户名、盘符或工厂目录；运行需要 Python 3.12 和 Node.js 22.12+。QQ 授权的安全存储使用 Windows DPAPI，macOS/Linux 尚未接入凭据后端。

全新克隆后，在项目目录运行（`py -3.12` 也可替换为本机 Python 3.12 的可执行文件）：

```powershell
py -3.12 .\scripts\setup_runtime.py
npm ci
npm run setup:desktop
# 可选：本机 Basic Pitch 分析环境和模型，显式下载，不影响播放
.\.venv\Scripts\python.exe -I -B .\scripts\setup_analysis.py
npm start
```

**Electron：**打开窗口即启动专属后台；关掉最后一个窗口即退出，后台和分析子进程随之结束。不驻托盘、不注册服务、不设置开机启动、不启动 QQ 音乐主程序。后台使用随机回环端口，不与网页助手抢端口；不需要手动启动服务，也没有网页模式的 24 小时到期。

创建本机快捷方式：`powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\create-shortcut.ps1`。完成后双击本目录的 **talk 播放器.lnk**。也可运行 `scripts/open-desktop.ps1`；快捷入口不依赖启动一个 Node 控制台，不修改系统执行策略。

仍保留网页兼容入口：`scripts/open-player.ps1`，默认 <http://127.0.0.1:43180/>，网页助手仍有 24 小时 TTL。网页助手是独立的旧入口，不会因为 Electron 退出而被误杀。不要同时在两种入口播放，以免各自累计收听。

## 本机配置

默认无需配置文件。需要覆盖时复制 `config.example.json` 为 **`config.local.json`**（Git 忽略），只修改实际需要的字段。相对路径始终相对项目根目录，非当前终端目录。

- `python`：固定 QQ SDK 的 Python 3.12 虚拟环境，可复用已有经过校验的环境。
- `data_dir`：收藏、队列、听歌记录、歌词与音频缓存目录；默认 `.private`。
- `qq_session_dir`：QQ SDK 的独立授权与设备文件目录；默认 `.private/qq`。已有授权可只在本机指向原目录，无需复制或提交凭据。
- `analysis_python`、`basic_pitch_model`：独立分析环境与模型位置。
- `port`、`ttl_seconds`：仅控制网页入口；Electron 固定使用随机回环端口和窗口生命周期。

可用 `TALK_CONFIG_FILE` 指定另一个本机配置文件；路径字段可用 `TALK_PYTHON`、`TALK_DATA_DIR`、`TALK_QQ_SESSION_DIR`、`TALK_ANALYSIS_PYTHON`、`TALK_BASIC_PITCH_MODEL` 覆盖。未知字段与错误类型会拒绝启动。配置中不放密码、Cookie 或签名音源 URL。

**代码可迁移，授权不可跨设备复制使用。** 在另一台 Windows 设备上重新扫码；DPAPI 凭据绑定原 Windows 用户/设备，不将解密凭据搬运到 GitHub。

## 操作

- 搜索框输入歌曲或歌手，回车搜索；列表底部「更多」加载下一页。
- 点击歌曲名或行首播放键播放；底栏暂停、切歌、拖动进度、调音量。
- 循环图标切换列表循环、随机、单曲循环；单曲模式图标高亮。
- 心形收藏；歌曲右侧「…」加入队列、设为下一首、加至列表。
- 播放列表「+」创建；「…」重命名、删除；列表内歌曲「…」移除。
- 队列图标打开队列，可移除单曲或清空。清空队列不等于暂停当前歌曲。
- 左侧柱形图「听歌」查看 7 天／30 天／全部统计、常听歌曲与歌手、最近播放；点歌曲可播放，点歌手可搜索。
- 底栏「详情」打开当前歌曲；窄屏入口在搜索框右侧。歌词随进度高亮，点有时间的歌词可跳转；箭头图标切换跟随，下载图标导出 LRC，循环图标重新提取。没有歌词时不会伪造。
- 详情「分析」点击「分析」在本机跑模型，结果保存后可以「重算」。无需播放歌曲，也不会因此产生听歌记录。分析时原播放不会被模型暂停。
- 账号图标打开授权；本版公开 QQ 扫码入口。已有有效授权无需重复扫码；重新授权只在主动点击时发起。
- 空格播放或暂停，`/` 聚焦搜索；输入框和弹窗内不会抢占空格。浏览器支持时可使用系统媒体键。

刷新不会自动播放。收藏、列表、队列、音量、播放模式和最近播放位置会保存；再次点击播放恢复当前位置。

## 数据与授权

收藏和列表属于 **talk 本机资料库**，不会修改 QQ 音乐账号中的收藏或歌单。`data_dir/library.sqlite3` 保存资料、播放记录及歌词／分析缓存，不是云同步。请勿在播放器运行时直接编辑数据库。

## 听歌统计口径

- 从此版本开始记录；此前下载、缓存、搜索过的歌不会倒填为听过。测试记录在独立 QA 数据库，不会导入你的主资料库。
- 依据本页面媒体时钟与实际经过时间累计，暂停、缓冲、拖动跳过的区间、浏览器静音或音量为 0 不计；浏览器后台仍正常播放则继续计。电脑休眠等大间隔宁可少计，不补造。
- 一次播放累计达到 **30 秒或曲长一半（较小者）**算 1 次；暂停再播沿用本次，切歌／结束后重播为新的一次。短听仍有记录和时长。至少覆盖 **90% 不重复音频区间**才标记完成，拖到结尾不算听完。
- 每约 10 秒和暂停／跳转／关闭时保存，网络重试去重；突然崩溃可能损失末尾未送达部分。按心跳到达的北京时间归日，跨午夜可能有约一个心跳周期的归日误差。
- 「全部」汇总全部已记录数据，趋势图仍展示近 30 天；最近播放按全局最新记录排列，不随统计范围截断。
- 统计是浏览器播放观察值，不能确认人是否真的听了、系统音量是否静音或扬声器是否出声。多人／多页面同时播放会各自记录；合唱暂按平台提供的歌手显示字符串聚合。

## 歌词与分析

歌词通过本人已有授权和同一 QQ SDK 按所选歌曲 ID 获取；解析 LRC／QRC／纯文本、偏移、多时间标签，缓存 7 天，可手动刷新。实际已验证《晴天》63 个时间标签及 LRC 导出。并非每首歌都有歌词或翻译；歌词内容仍属于对应权利人。

模型采用 [Spotify Basic Pitch 0.4.0](https://github.com/spotify/basic-pitch/tree/v0.4.0)，ONNX Runtime CPU、本机 2 线程。默认分析 **0:30–1:00 的 30 秒片段**，短歌自动选择可用片段；来源仍走本人授权与完整音频校验，不上传音频、歌词或凭据到模型服务。首次运算可能需几十秒，随后可读取保存结果。

页面展示模型给出的**复音音符候选／候选音域／钢琴卷帘**，另用 librosa 计算估计 BPM、频谱重心和 RMS 能量。《晴天》真实跑出 440 个候选音符、估计 136 BPM。它们是估计，不是人工校准结果；音符 activation 不是经过校准的概率。

**这不是已经完成的主旋律提取、准确调性识别、情绪冷暖判断或五线谱生成。** 人声、伴奏与混响会混在候选中；不能把频谱重心当成主观冷暖、把 RMS 当成情绪。后续可独立加入人声分离、情绪专用模型和人工修谱，本次先交付可复现的简单音乐内容分析。

## 授权与隐私

登录凭据保存在配置的 `qq_session_dir/credential.dpapi`，由当前 Windows 用户 DPAPI 加密。浏览器不会获得凭据或平台签名音源地址；没有导出客户端 Cookie，也不读取官方客户端内存。本机配置仍可指向此前扫码确认的授权，重构不会要求无故重新登录。

每次播放会检查服务端登录和该录音文件的授权。普通 MP3 在完整下载、帧扫描和非静音完整解码通过后才供浏览器播放；首次加载需要等待，后续可复用已验证缓存，但仍请求该文件授权。不回退到匿名、试听或其他歌手版本，不解密官方 `.mgg` 缓存。当前音质为 128 kbps MP3，不是无损。

登录失效时尝试一次 SDK 续期，失败才要求重新扫码。**真实过期续期尚未实测，不保证登录永久有效**。重新授权失败不会删除已有凭据；成功切换授权会清除旧的内存音源许可。此前独立授权页已实际扫码成功；新播放器内的授权弹窗已检查已有授权和不自动生成二维码，但尚未再次完成扫码，不能把两者视为同一次端到端验收。

音频仅保存在 `data_dir/audio`，最多 12 首且约 150 MiB；专辑封面缓存最多 400 张。不是离线曲库或歌曲导出工具。关闭 Electron 窗口停止播放并退出专属后台；凭据和资料库保留。网页模式关闭页面只停止该页面播放，独立助手按期限退出。

服务仅监听 `127.0.0.1`，校验 Host、Origin、CSRF，不开放 CORS，不暴露私有目录。它面向可信的个人设备，不是多用户安全边界；不要转发端口、公开部署或分享私有文件。手机尺寸布局已经适配，**不代表手机能跨设备访问这个本机地址**。

## 开发与复测

```powershell
.\scripts\test.ps1
.\scripts\start-qa.ps1
```

模型环境已在当前设备安装。检查或重建（仅安装到本项目的私有新环境，不改 QQ 环境／全局 Python）：

```powershell
$python = '.\.venv\Scripts\python.exe'
& $python -I -B .\scripts\setup_analysis.py --check-only  # 无下载、无安装
& $python -I -B .\scripts\setup_analysis.py               # 显式安装／复验
```

版本锁在 `analysis/basic_pitch/requirements.lock.txt`；5 个未改上游源码和 ONNX 模型 SHA-256 在 `sources.lock.json`。安装脚本只解压固定散列 wheel 的白名单文件，不安装其 TensorFlow 依赖；授权播放与分析运行本身不联网下载模型。模型许可证在 `analysis/basic_pitch/LICENSE-Spotify`。

QA 入口为 `http://127.0.0.1:43181/`，数据库为 `data_dir/qa/library.sqlite3`，默认 30 分钟自动退出，不覆盖主播放器资料或启动指纹。QA 使用同一 Windows 用户；除显式覆盖 `TALK_QQ_SESSION_DIR` 外可使用本人已有独立授权，不创建另一个桌面或系统账号。`npm run verify:desktop` 则使用全新的临时数据/授权目录，不访问账号，实际验证后台启动、主动关闭及控制管道 EOF 后端口释放。

文件分层：`web/` 原生 HTML/CSS/JS；`src/library.py` SQLite；`listen_store.py` 收听统计；`lyric_parser.py` 歌词；`insights.py` 缓存与结果投影；`analysis_runner.py` 固定模型子进程；`src/bridge.py` QQ 适配器；`src/server.py` 回环 HTTP 与异步任务；`analysis/basic_pitch/` 本机模型；`scripts/` 启动、安装及测试。`web-next/` 仅留作增量验收预览（`start-qa.ps1 -Preview`），正式入口使用 `web/`。

QQMusicApi 0.8.2 固定提交、源码散列、带散列依赖锁与必要适配器均已收进本仓库：`src/providers/qq/`、`requirements/qq-windows-py312.lock`。不再要求旁边有某个日期的实验目录，不新增全局安装、不修改第三方 SDK。第三方 SDK 使用 GPL-3.0-or-later，原许可证与版本来源见 `THIRD_PARTY.txt`。
